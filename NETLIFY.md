# Déployer Boutilo avec Netlify

Netlify héberge l'interface et sert de relais vers `/api/*`. Le serveur Python ne fonctionne pas comme fonction Netlify avec la configuration actuelle : il faut l'héberger séparément sur une plateforme prenant en charge Python et un service HTTP, avec HTTPS. La base PostgreSQL reste dans Supabase. Le déploiement n'a pas encore été validé en ligne.

1. Dans Supabase, exécuter `schema-supabase.sql` dans le SQL Editor. Ce schéma initialise une base vide ; il ne migre pas SQLite.
2. Déployer le serveur Python à partir de ce dépôt sur un hébergeur Python HTTPS. Installer `requirements.txt`, lancer `python server.py`, définir `DATABASE_URL` côté serveur avec la chaîne PostgreSQL du pooler Supabase et `COOKIE_SECURE=1`. Le serveur utilise le port fourni par `PORT`. Ne jamais déposer les secrets dans le dépôt ou le navigateur. Ce serveur standard est destiné à un pilote ; une revue et un serveur adaptés sont nécessaires avant toute exploitation publique.
3. Vérifier que l'API répond à `/api/health`, puis importer le dépôt dans Netlify. Dans les variables de build Netlify, définir `BACKEND_URL` avec uniquement l'origine HTTPS de l'API (par exemple `https://exemple-hebergeur.example`, sans chemin ni identifiants). `DATABASE_URL` est uniquement sur le serveur Python, pas dans Netlify.
4. Netlify utilise `netlify.toml` : `python3 build_netlify.py` et dossier `public`. Le build échoue volontairement si `BACKEND_URL` manque ou est invalide. Une adresse `*.netlify.app` est fournie sans acheter de domaine.
5. Sur l'adresse Netlify, vérifier `/api/health` via le relais, créer deux comptes fictifs, tester l'isolation des boutiques, produit, vente, déconnexion, reconnexion, refus des modifications périmées et partage WhatsApp. Vérifier que `server.py` et le SQL ne sont pas accessibles comme fichiers statiques. Vérifier que les cookies sécurisés et la réponse aux requêtes GET/POST/PUT fonctionnent à travers le relais.

La configuration n'a pas encore été testée sur Netlify, Supabase ou un hébergeur Python réel. Ne pas utiliser de données réelles avant la validation de la sécurité, des sauvegardes et des fonctionnalités de récupération du compte. Le limiteur en mémoire n'est pas adapté à plusieurs instances. Les offres gratuites peuvent avoir des limites et changer ; vérifier leur disponibilité avant le choix de l'hébergeur.
